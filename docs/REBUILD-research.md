## voice-consistency
## How production voice apps keep a clone consistent — and how to add energy without breaking identity

**1. The reference clip is the product.** Every vendor says the same thing: the model copies *everything* in the clip — speed, inflection, breathing, mouth clicks — so a soft, slow reference yields a soft, slow clone ([ElevenLabs help](https://help.elevenlabs.io/hc/en-us/articles/13416206830097-Are-there-any-tips-to-get-good-quality-cloned-voices)). Boson recommends 5–30 s of clean single-speaker speech plus a *verbatim* transcript including fillers ([Boson voices docs](https://docs.boson.ai/models/higgs-audio-tts/voices)); the Qwen3-TTS guide finds quality plateaus past ~15 s and that transcript-conditioned cloning lifts SIM from ~0.75 to ~0.89, and warns "monotone reference → monotone output" ([ocdevel](https://ocdevel.com/blog/20260302-qwen-tts-voice-cloning)). ElevenLabs: no compression/EQ before cloning, normalise to −3 dBFS, cut disruptive breaths, keep one mic/session, consistent tone throughout ([ElevenLabs tips](https://elevenlabs.io/blog/7-tips-for-creating-a-professional-grade-voice-clone-in-elevenlabs)). Implication for Bag: the cheapest energy gain is a *different 10–20 s window of the same narrator* — his most animated passage, same session, no whisper/shout in it (single timbre). Higgs's `references` field accepts a list ([SGLang cookbook](https://sgl-project.github.io/sglang-omni/cookbook/higgs_tts.html)); how multiple refs combine is undocumented, so treat multi-ref as an experiment scored by the gate below, and keep total reference ≤30 s (the Studio app hard-caps at 30 s; ComfyUI trims silence at −42 dB) ([Studio](https://github.com/Saganaki22/Higgs-Audio-v3-Studio), [ComfyUI](https://github.com/Saganaki22/Higgs_v3-TTS-ComfyUI)).

**2. Freeze the conditioning.** SGLang-Omni caches encoded reference codes in a 256-entry LRU keyed on file path+size+mtime and partitions RadixAttention prefix cache by reference ([PR #605](https://github.com/sgl-project/sglang-omni/pull/605), [LMSYS blog](https://www.lmsys.org/blog/2026-06-04-higgs-audio-v3-tts/)); keep one immutable reference file per persona so the key never changes (gain is modest: encoder ≈14 % of pipeline, AR decode 79 %). Boson's hosted API does the same via `/v1/audio/voices` → `voice_id`. Sampling: 0.8 / top_k 50 / top_p 1.0 / max_new_tokens 1024 is the reference setting everywhere ([HF card](https://huggingface.co/bosonai/higgs-audio-v3-tts-4b), ComfyUI). `seed` is honoured, but batched execution is only reproducible with `--enable-deterministic-inference` (FlashInfer/FA3/Triton; FlashInfer loses radix cache) ([SGLang docs](https://docs.sglang.io/advanced_features/deterministic_inference.html)). Seed pinning gives repeatability of a *fixed line* (perfect for the phrase bank); it does not make different sentences sound alike — the gate does.

**3. Gate every output on speaker similarity, not pitch.** This is how TTS is evaluated: cosine between speaker embeddings of reference and output. Seed-TTS-eval uses WavLM-large-SV; human ground truth scores 0.73 (en)/0.75 (zh), Seed-TTS 0.762 ([Seed-TTS](https://arxiv.org/html/2406.02430v1)). CPU-friendly choices: `pip install resemblyzer` (256-d, English-centric, ~1000× real time on a GTX 1080) ([Resemblyzer](https://github.com/resemble-ai/Resemblyzer)); SpeechBrain ECAPA (192-d, 16 kHz, cosine, default same-speaker threshold 0.25, EER 0.8 %) ([SpeechBrain](https://huggingface.co/speechbrain/spkrec-ecapa-voxceleb), [source](https://raw.githubusercontent.com/speechbrain/speechbrain/develop/speechbrain/inference/speaker.py)); `microsoft/wavlm-base-plus-sv` (16 kHz, example threshold 0.86, "dataset-dependent") ([HF](https://huggingface.co/microsoft/wavlm-base-plus-sv)). Absolute thresholds are meaningless across models — calibrate per persona (see recommendations). Caveat: shouted and whispered speech systematically shift embeddings and degrade verification ([vocal effort](https://arxiv.org/abs/2305.02147), [whisper](https://arxiv.org/abs/2604.20229)), which matches your measurement that `whispering` flips timbre — so keep per-style baselines and ban style tags for Bag. Pair with an ASR gate: best-of-N selection by lowest WER/CER against the script is standard ([Align2Speak](https://arxiv.org/html/2509.21718v1)); use Whisper as verifier — a verifier from the TTS's own model family inflates scores ([BoN confound](https://arxiv.org/html/2607.08256)). Your server batches concurrent takes (2 in ~1.07 s), so N=2–3 in parallel is nearly free.

**4. Tags: which keep identity.** Docs say delivery tokens go first ([HF card](https://huggingface.co/bosonai/higgs-audio-v3-tts-4b)), but the ComfyUI author found a strong emotion tag as *first token* "overpowers the reference-speaker conditioning"; the fix is to emit one word, then the tag with the next word attached without a space; emotion tags are kept local per chunk while style/prosody carry over ([ComfyUI](https://github.com/Saganaki22/Higgs_v3-TTS-ComfyUI)). Speed changes lower similarity in clone mode ([higgstts.app](https://higgstts.app/how-to-use-higgs-tts)) — consistent with your finding that speed tokens are ignored anyway.

**5. Generated clip as reference — valid, one hop only.** Qwen3-TTS documents "design a voice → freeze that output as the clone prompt" as the official consistency workflow ([ocdevel](https://ocdevel.com/blog/20260302-qwen-tts-voice-cloning)). But recursive use drifts: after 10 hops CosyVoice3-RL's SIM fell 67→46 and weak models collapsed (noise, muffling, WER >40); handing F5-TTS a high-quality reference at hop 6 sharply restored it ([I2D](https://arxiv.org/html/2603.24430)). So: one synthetic hop from the human clip, chosen by SIM *against the human clip*, never chained.

**6. Identity-preserving "voice changer".** Order: HPF → EQ → compressor → de-esser → limiter → loudness ([async](https://async.com/blog/how-to-eq-voice-for-podcast/)). Human pitch identification stays good at 1 semitone and collapses past 3 (upward worse) ([pitch study](https://www.academia.edu/4425931/Effect_of_Pitch_Modification_On_The_Voice_Identification_Of_The_Speaker)); ASV EER jumps 2 %→38 % under pitch scaling ([disguise](https://arxiv.org/pdf/2009.06863)); 10–20 % formant shifts are audible character changes ([Sonarworks](https://www.sonarworks.com/blog/learn/formant-shifting-explained-changing-gender-and-character-in-ai-vocals)). Energy is loudness/dynamics/presence, not pitch — leave F0 alone. Rubber Band `-F` preserves formants when shifting ([manpage](https://manpages.debian.org/unstable/rubberband-cli/rubberband.1.en.html)). For a real timbre-locked changer, zero-shot VC (seed-vc: 1–30 s ref, keeps source prosody, ~430 ms RTX 3060; GPL-3, archived) can re-stamp an energetic take with Bag's timbre ([seed-vc](https://github.com/Plachtaa/seed-vc)), the "VC as post-processing" pattern from [Amazon](https://assets.amazon.science/ba/cf/51543bab499dab771d246b475c8b/voice-filter-few-shot-text-to-speech-speaker-adaptation-using-voice-conversion-as-a-post-processing-module.pdf).

KEY: - Re-cut the reference from the SAME narrator recording: pick his most animated 12-20 s (no whisper/shout, one mic, one session), trim silence at -42 dB, normalise to -3 dBFS, NO EQ/compression, verbatim transcript incl. fillers. Store as one immutable file per persona so SGLang-Omni's ref-code LRU / RadixAttention prefix cache key never changes; run the server with reference-code caching on (SGLANG_OMNI_HIGGS_REF_CODE_CACHE=1 or its server-option equivalent).
- Pin sampling: temperature 0.8, top_k 50, top_p 1.0, max_new_tokens 1024; fixed seed per phrase-bank line (so repeats are bit-identical) and rotating seeds for free lines. If exact reproducibility matters, start SGLang with --enable-deterministic-inference on FA3 or Triton (FlashInfer drops radix cache).
- Replace the F0 gate with a speaker-similarity gate: embed the reference once (SpeechBrain ECAPA 192-d, or WavLM-base-plus-sv; Resemblyzer as the zero-setup fallback), score each take by cosine at 16 kHz. Calibrate, do not copy thresholds: generate 30 neutral Bag lines, take median SIM as the persona baseline, reject below baseline - 0.05 or the 10th percentile (whichever is stricter). ECAPA default 0.25 / WavLM 0.86 / Resemblyzer ~0.75 are only sanity bounds.
- Rejection sampling: fire N=2 (N=3 for lines >8 s) concurrent requests (server batches them, ~1.07 s for 2), hard-filter on Whisper CER <= 5 %, then pick max SIM. Keep whisper (not a Higgs-family model) as the verifier.
- Tag policy for Bag: allow only prosody tokens (pause/long_pause, expressive_high) plus a whitelist of mild emotions (bitterness, disgust, pride, amusement) measured by SIM on 20 lines each; ban style:whispering/shouting/singing and pitch_low/high. Emit the tag AFTER the first word with the next word attached (no space) instead of as the first token.
- Energy via DSP, not model: HPF 50-60 Hz gentle slope (F0 is 74-113 Hz; the usual 80 Hz would thin the fundamental), presence +2-3 dB around 3 kHz (bell, Q~1), air shelf +1-2 dB at 10 kHz, compressor 3:1 attack 5 ms release 100 ms for ~4 dB gain reduction, de-esser 6-8 kHz, exciter only above ~5 kHz at <=1 % THD, breath reduction -9 to -12 dB (RX Breath Control gain mode / Waves DeBreath energy threshold -30 dB), limiter -2 dBTP, level to -16 LUFS integrated. Apply the same chain to every take of every persona.
- Pitch/formant/tempo limits so identity survives: |pitch| <= 1 semitone with formant preservation (rubberband -F), formant shift <= 3 %, tempo change <= 10 %; never larger, never stacked. Prefer 0 pitch shift for Bag; he is deep already.
- Optional one-hop bootstrap: generate 40 energetic lines with the whitelisted tags, keep the 10-20 s stretch with the highest SIM vs the HUMAN clip, and use it as a second (or replacement) reference. Never re-derive a reference from a reference; always score against the original human recording.
- Optional identity lock via voice conversion: if energetic takes still drift, run them through zero-shot VC (seed-vc, GPL-3, archived; fits on GPU 1 alongside TTS) with the human clip as timbre reference, then re-gate. Only adopt if it beats the DSP chain on SIM in an A/B.
- Consistency dashboard in the UI: per persona show reference waveform+transcript, baseline SIM, and for each generated line its SIM/CER and a red/amber/green badge; expose only two user knobs (energy 0-100 mapping to compressor/presence amounts, and 'strict/loose' gate). Drop the 15 delivery modes and the LLM director.

## app-architecture
## Industry-grade local TTS service for "Mr. Bag" — research report

**Bottom line.** The current `server/orchestrator.py` (1,510 lines, one module, every route a sync `def`, synthesis behind a lock, ~15 delivery modes plus an LLM director) is a research notebook, not a service. The pattern used by mature local speech servers is a thin, staged pipeline with content-addressed render IDs, a single-worker priority queue, a persistent line library, and a QA gate that measures the *voice* — not the delivery. Consistency comes from holding inputs constant (reference, seed, sampler, no style tags), not from post-hoc stretching.

### 1. Request pipeline: validate → canonicalize → render-id → cache → queue → synth → QA → post → store
Home Assistant's TTS integration is the cleanest reference for idempotent renders: the cache key is `sha1(message)_language_blake2s(sorted options)_engine`, files persist across restarts, and a short-lived memory cache fronts the disk cache ([HA tts source](https://raw.githubusercontent.com/home-assistant/core/dev/homeassistant/components/tts/__init__.py)). Adopt the same: `render_id = hash(voice_id, voice_version, canonical_text, seed, sampler, postchain_version)`. A second identical request (same line at the table next week) is a cache hit, never a regeneration.

Kokoro-FastAPI shows the text stage done right: deterministic sentence-boundary chunking with min/max token targets, normalization, `[voice:name]` inline speaker tags, and word-level timestamps via sidecar JSON ([Kokoro-FastAPI](https://github.com/remsky/Kokoro-FastAPI)). Keep chunking rule-based and versioned; drop the LLM director from the render path entirely.

### 2. Job queue: ComfyUI's model
ComfyUI runs one worker thread over a thread-safe priority queue with `/prompt` (returns `prompt_id` + position; `front=true` jumps the line), `/queue` (delete/clear), `/interrupt`, `/history`, and a `/ws` channel emitting `status`, `executing`, `progress`, `executed` ([ComfyUI routes](https://docs.comfy.org/development/comfyui-server/comms_routes)). Mirror it: one render worker (the GPU is the serial resource), three priorities (live table line > pre-render > batch), cancel by job ID, and a WS feed the UI subscribes to. For durability across restarts, `persist-queue`'s `SQLiteAckQueue` gives ack/nack/ack_failed semantics with WAL mode ([persist-queue](https://github.com/peter-wangxu/persist-queue)). Because SGLang batches concurrent requests (your measured 1.07 s for two parallel takes vs 1.79 s sequential), the worker may fan a *single job* into N concurrent takes, but never runs two jobs at once.

### 3. Streaming vs full clips
SGLang-Omni streams raw 16-bit PCM (`stream:true, response_format:"pcm"`, ~20-frame first chunk) ([Higgs cookbook](https://sgl-project.github.io/sglang-omni/cookbook/higgs_tts.html)), and the serving stack shares KV cache across requests with the same reference clip via RadixAttention `extra_key` partitioning ([LMSYS blog](https://www.lmsys.org/blog/2026-06-04-higgs-audio-v3-tts/)). But browser MediaSource is "not Baseline", limited on iOS/Safari, and needs fragmented MP4/WebM ([MDN MediaSource](https://developer.mozilla.org/en-US/docs/Web/API/MediaSource)); practitioners fall back to WebSocket binary frames + Web Audio, or MP3 chunked transfer ([FastAPI WS audio](https://hexshift.medium.com/top-ten-tips-for-streaming-real-time-audio-with-websockets-in-fastapi-21eaea6c7bde)). For a D&D table, lines are 1–8 s and a QA gate needs the whole clip, so: **full WAV clips for the library and phrase bank; PCM-over-WebSocket streaming only for the live `/converse` path**, with the library fed asynchronously.

### 4. Voice consistency (the user's actual complaint)
Three industry patterns:
- **Hold the clone inputs constant.** Pre-encode the reference once (`reference_codes` + `reference_text` in the cookbook) and pin `seed`, `temperature`, `top_k/top_p` per voice in config. openedai-speech stores exactly this — per-voice reference file plus sampler params in `voice_to_speaker.yaml` ([openedai-speech](https://github.com/matatonic/openedai-speech/blob/main/voice_to_speaker.default.yaml)).
- **Render related parts in one request** or with continuity context. ElevenLabs' request stitching exists precisely because separate chunks produce "abrupt changes in prosody" ([ElevenLabs stitching](https://elevenlabs.io/docs/eleven-api/guides/how-to/text-to-speech/request-stitching)). Higgs has no such field, so the substitute is: one generation per line, chunk only above ~400 chars, same seed across chunks.
- **Identity lock as a post-stage.** AllTalk applies RVC as a "TTS-to-TTS pipeline" with pitch, index rate, filter radius, and protect settings, LRU-caching three RVC models ([AllTalk RVC](https://github.com/erew123/alltalk_tts/wiki/RVC-(Retrieval%E2%80%90based-Voice-Conversion))); `rvc-python`/RVC_CLI expose batch inference with `rmvpe` F0 ([RVC_CLI](https://github.com/jaaari/RVC_CLI)). Train one RVC model on ~10 min of the *approved* Bag renders and it collapses timbre drift from emotion tags into one voice — the "voice changer" the user asked for.

Note `docs/milestone-0.md` records the tokenizer has **no `pitch_low`**; encode the verified token list as data and refuse unknown tags.

### 5. Library, config, pre-rendering
Use SQLite (`voices`, `lines`, `renders`, `jobs`) plus `data/renders/<voice>/<render_id>.wav`. `voices.yaml` holds reference path, transcript, seed, sampler, allowed tags, RVC model, LUFS target, F0 band. On boot and on voice change, enqueue all phrase-bank lines at low priority — the table then hits cache. neosun100's higgs-audio-web is a reasonable single-container layout (Web UI + REST + voice library) but has no queue or cache, which is the gap you're filling ([higgs-audio-web](https://github.com/neosun100/higgs-audio-web)).

### 6. Health, degradation, observability
Split `/healthz` (process alive) from `/readyz` (TTS server up, reference encoded, warm-up render passed); readiness can also reflect queue backlog ([FastAPI probes](https://medium.com/@bhagyarana80/fastapi-health-checks-and-timeouts-avoiding-zombie-containers-in-production-411a27c2a019)). When the 27B is not resident (cold load 15–90 s), the UI must still serve the phrase bank, script mode and cached lines; only `/respond` degrades. Speaches shows the opposite policy — load-on-demand, unload-on-idle ([Speaches](https://github.com/speaches-ai/speaches)) — the right one for STT, wrong for the LLM. Expose Prometheus via `prometheus-fastapi-instrumentator` plus custom histograms per stage (`chunk`, `synth`, `qa`, `post`) and gauges for queue depth and cache hit rate ([instrumentator](https://github.com/trallnag/prometheus-fastapi-instrumentator)).

### 7. Test harness
Golden set: ~30 Slovak lines per voice, committed with approved WAVs. Per render assert: whisper CER ≤ threshold; F0 median inside the voice band (74–113 Hz for Bag); integrated loudness within ±1 LU of target via `pyloudnorm` (ITU-R BS.1770-4) ([pyloudnorm](https://github.com/csteinmetz1/pyloudnorm)); duration ratio vs syllable count; optionally speaker-embedding cosine similarity to the reference ([TTS metrics](https://apxml.com/courses/speech-recognition-synthesis-asr-tts/chapter-1-modern-speech-processing-foundations/advanced-evaluation-metrics)). Run it in CI against a live TTS container and on every voice/config change.

### 8. Repo layout and UI
`app/{api,queue,pipeline/stages,store,voices}`, `web/`, `configs/voices.yaml`, `tests/golden/`, `docker/`. The UI needs live queue state, an audio player and hotkeys — the htmx essay itself concedes SPAs win for "extensive client-side state" and "real-time frequent updates" ([htmx essay](https://htmx.org/essays/when-to-use-hypermedia/)); a small Preact/Alpine page with one WebSocket is enough, no build step required.

KEY: - Replace the 1,500-line orchestrator with a staged pipeline (validate -> canonicalize -> render_id -> cache -> queue -> synth -> QA gate -> post -> store); the LLM director, 15 delivery modes, PSOLA drawls and per-sentence time-stretch leave the render path entirely.
- Make every render idempotent: render_id = hash(voice_id, voice_version, canonical_text, seed, sampler params, post-chain version), stored in SQLite with the WAV on disk (Home Assistant TTS cache pattern); identical requests are cache hits forever.
- Adopt ComfyUI's queue model: one GPU worker over a priority queue (live line > pre-render > batch), job IDs, /interrupt-style cancel, history, and a WebSocket feed of status/progress; persist it with persist-queue SQLiteAckQueue so restarts do not lose work.
- Lock voice consistency at the input: pre-encode the approved Bag reference once (reference_codes + transcript), pin seed/temperature/top_k/top_p per voice in voices.yaml (openedai-speech pattern), forbid emotion/style/whisper tags for the Bag voice by default, and render each line in a single request with a stable seed across chunks.
- Add RVC as an optional identity-lock post-stage (AllTalk pattern): train one model on ~10 minutes of approved Bag renders, apply with rmvpe F0 and small pitch offset; this is the 'voice changer' that collapses timbre drift into one voice.
- Ship full WAV clips for the library and phrase bank (QA gate needs the whole clip; MediaSource is not Baseline and weak on Safari); use PCM-over-WebSocket streaming only for the live /converse path and write its output into the library asynchronously.
- Pre-render the whole phrase bank for every active voice at boot and on any voice/config change, at low priority, so the table never waits; expose cache hit rate as a metric.
- Separate /healthz (alive) from /readyz (TTS up, reference encoded, warm-up render passed) and degrade gracefully: when the 27B LLM is not resident, phrase bank, script mode and cached lines keep working; only /respond reports degraded.
- Build a golden-audio test harness: ~30 Slovak lines per voice with approved WAVs; assert whisper CER, F0 median within the voice band (74-113 Hz for Bag), integrated loudness within +/-1 LU via pyloudnorm (BS.1770-4), duration-per-syllable ratio, and optionally speaker-embedding similarity; run on every voice or config change.
- Instrument with prometheus-fastapi-instrumentator plus per-stage histograms (chunk, synth, qa, post), queue depth and cache-hit gauges; keep the UI a small no-build SPA (Preact/Alpine + one WebSocket) with hotkeys and a soundboard of pre-rendered lines rather than an htmx page, since it is state- and real-time-heavy.

## dnd-ux
## What a DM needs from a voice tool at the table (research, Sept 2026)

Method note: reddit.com is unreachable from this environment; DM forums (D&D Beyond, EN World, Syrinscape, Roll20, Convai, GitHub issues) and product docs stand in.

### 1. Interaction patterns that survive live play
The products DMs keep using converge on one rule: one deliberate tap, then eyes back on the players. Syrinscape sells exactly this: "One click fades in ambience," "Turn the page, click the matching scene," "Your attention stays on your players" ([Syrinscape](https://syrinscape.com/dnd-soundboard-sound-effects/)). An EN World DM: "click one button and kick off the sounds and often don't have to mess with it again until the scene changes" ([EN World](https://www.enworld.org/threads/syrinscape.444735/)). Presets are named by table moment ("Battle Begins", "Defeat is Imminent") and crossfade automatically ([Nerdist](https://nerdist.com/article/syrinscape-review-a-great-soundtrack-app-for-tabletop-rpgs/)). Anything requiring search is an "attention tax"; the same reviewer builds one-click macros and even hands them to players ([Crit Hit Brit](https://www.crithitbrit.com/roll20-syrinscape-soundboard/), [long-term review](https://www.crithitbrit.com/syrinscape-long-term-review/)).

Hands-free control is a real demand, not a gimmick: Kenku FM ships an HTTP remote plus a Stream Deck plugin ([Kenku FM](https://github.com/owlbear-rodeo/kenku-fm)); users still ask for phone/tablet remotes ([issue #53](https://github.com/owlbear-rodeo/kenku-fm/issues/53)). Voicemod tells DMs to bind a keyboard shortcut per voice ([Voicemod](https://www.voicemod.net/en/dd-voice-changer/)). Sound Show (a live-performance soundboard used by GMs) exposes "fade only sounds, only visuals, or everything at once" so nothing needs the mouse ([Sound Show](https://impronivers.itch.io/sound-show/devlog/964030/update-10062025-stream-deck-support)). The Stream Deck Pedal works because it has three pedals, a toggle mode, and springs stiff enough to rest feet on ([PremiumBeat](https://www.premiumbeat.com/blog/stream-deck-pedal-review/)).

Platform soundboards fail the D&D case: Discord caps clips at 5 s / 512 KB MP3 ([Discord](https://discord.com/blog/how-to-use-the-discord-soundboard-add-more-sounds)); Roll20's jukebox: "Sometimes the files play, sometimes they don't, sometimes there's an echo" ([Roll20 forum](https://app.roll20.net/forum/post/5344460/)).

### 2. Latency tolerance
Two regimes. For a DM-triggered line, the ceiling is about four seconds: a CUI'25 study found "latency above 4 seconds degrades quality of experience," and that "natural conversational fillers improve perceived response time, especially in high-delay conditions" ([arXiv 2507.22352](https://arxiv.org/abs/2507.22352)). Typed-then-spoken improv was rejected on D&D Beyond precisely because it "creates 30-second delays that break immersion" ([D&D Beyond](https://www.dndbeyond.com/forums/dungeons-dragons-discussion/dungeon-masters-only/180095-researching-voice-tools-and-willing-to-create-one)); Convai users report 10 s NPC replies as unusable ([Convai forum](https://forum.convai.com/t/npc-takes-around-10-seconds-to-response-how-i-can-decrease-the-response-time/2890)). For anything conversational (player talks, NPC answers), the bar is sub-300 ms time-to-first-audio ([Inworld](https://inworld.ai/resources/best-voice-ai-for-interactive-entertainment)) which a local Higgs pipeline cannot hit; so do not design a "talk to the Bag" mode.

### 3. Consistency vs. acting control
DMs ask for distinctness and recognisability, not acting. Experienced DMs signal an NPC with "Tone, Pace, Pitch, Volume" and warn that voice changers were "hard to understand" and got abandoned; one suggests TTS only for pre-recorded scene intros ([D&D Beyond](https://www.dndbeyond.com/forums/dungeons-dragons-discussion/dungeon-masters-only/227981-voicemod-voice-changer-ideas)). The author of an NPC speech-pattern cheat sheet: "I never roll an NPC speech pattern during a session, that would disturb me too much" ([itch.io](https://goupilverse.itch.io/speech-patterns-for-npcs-a-gm-cheat-sheet)). NPC Chronicles sells pro-recorded lines in ten fixed categories (Greetings, Offers, Pleas, Commands, Rejections, Farewells...) so the DM stops "worrying about trying to stay in character" ([NPC Chronicles](https://npcharacter.com/)). The ElevenLabs ecosystem hit the same drift problem the user measured: instant clones vary "in pitch and other times in intonation" per generation; fixes are a fixed seed, high stability, identical settings, and stitching ([podcastfy discussion](https://github.com/souzatharsis/podcastfy/discussions/156)). Foundry voice modules all persist per-actor voice settings and save every generated MP3 next to the NPC ([Talking Actors](https://github.com/acd-jake/acd-talking-actors), [VoiceGen](https://github.com/tirzah2/voicegen), [Archive of Voices Pro](https://foundryvtt.com/packages/archive-of-voices-pro)), and treat AI text as "drafts; tweak, expand, or ignore."

### 4. Roster, scenes, sentient items
Foundry integrations attach a default mood per scene and let one-shots be dragged onto a hotbar ([Syrinscape Controller](https://github.com/MetaMorphic-Digital/syrinscape-control)); ConversationHUD shows portraits of NPCs in a conversation and highlights "the currently active participant" ([Foundry](https://foundryvtt.com/packages/conversation-hud)). On sentient items, EN World's advice is blunt: it is "an additional NPC to the party that is always present. You'll need to be prepared to role-play the sword at all times," so limit its modes of expression and give it a catch phrase ([EN World](https://www.enworld.org/threads/sentient-weapons.268742/)). Mr. Bag needs a small, instantly reachable repertoire more than a director.

### 5. Mobile and tablet
DMs want control on a tablet and sound from the PC: "I've had to move from the table to my computer desk to switch sounds" ([Syrinscape forum](https://forum.syrinscape.com/t/control-pc-audio-with-tablet/4249)). Android kills audio when the app is backgrounded or the screen locks; the official workaround is a two-device split, control on the tablet, playback elsewhere ([Syrinscape forum](https://forum.syrinscape.com/t/syrinscape-online-player-android-app-not-playing-in-background/16666)). Desktop-sized sidebars are unusable on small screens.

### 6. Failure modes that end the tool's life
Long waits (above ~4 s, or 10-30 s), a voice that sounds like a different person on the next line, reads that are "too polished, eager" ([CharGen](https://char-gen.com/blogs/best-ai-dungeon-master-tools-2026)), an app that hangs "at a key point in the game flow," search that takes longer than doing the voice yourself, and audio dying when the DM opens the rules PDF.

KEY: - Table moment: a player reaches into the Bag. -> One-tap phrase board of pre-rendered Bag lines, grouped NPC-Chronicles style (Greetings, Insults, Refusals incl. Express mood with a post-processing 'voice changer' layer (small pitch/EQ/tempo/reverb presets) applied to the same clone, and cache every rendering by (persona, text) hash so repeats are bit-identical, as the Foundry ElevenLabs modules do.
- Table moment: an NPC walks into the tavern. -> Roster cards (portrait, name, two-line voice note, a stored 'signature line'). Tapping the card plays the signature line so the DM re-anchors the voice, and the card becomes the highlighted active speaker (ConversationHUD pattern). - Table moment: the party leaves the road and enters the dungeon. -> Scene presets: a scene bundles the roster subset, its phrase pages, and an ambience bed; one tap switches with a crossfade (Syrinscape mood pattern). Prep is 'name the scene, pick who is in it', not sound design.
- Table moment: the DM's hands are full of dice and the screen. -> Global hotkeys for the top 8 Bag lines, plus Stop-all, Repeat-last, and Ten-nie; expose the same actions over a LAN HTTP endpoint (Kenku Remote pattern) so a Stream Deck or 3-button foot pedal can drive them without touching the laptop.
- Table moment: the DM runs the game from the couch on a tablet. -> Client is a remote; audio always comes out of the workstation/Bluetooth speaker, never the tablet. Large touch targets, no sidebars, and state lives on the server so a locked phone or a switch to the rules PDF never kills a line.
- Table moment: ambience is playing when the Bag interrupts. -> Auto-duck the music bed by about 10 dB on speech start and restore on end; queue lines so two taps never overlap; one red Stop-everything button.

- Table moment: the night before the session. -> Script mode as batch prep: paste notes, mark [voice] lines, render everything overnight with the resident model; at the table the app is 95 percent cached playback and 5 percent improv, which is where the 4-second budget and the filler trick apply.

## Hidden couplings
- `pitch_low` and the gate are co-dependent (comment l.271): removing the token alone makes the gate reject more, so more re-rolls, so more seed variety. Remove both.
- `_score` uses `MODE_SPS`, so the take chosen is the one whose *speed* matches the mode, not the one closest to the reference.
- Chunk continuity (l.850-868) feeds the previous *tagged* chunk's 12 s tail as a second reference: drift compounds, and each temp file defeats the SGLang reference cache.
- `_TTS_LOCK = BoundedSemaphore(4)` vs `/script` 4 lines x 2 takes: contention is invisible, timings vary.
- `speed` set vs unset selects two different pipelines; a UI checkbox changes the algorithm.

## Where "different person" comes from (ranked)
1. Emotion/expressive/pitch_low tags on every line (`_lead_for`).
2. Best-of-2 across seeds with a pace-based scorer; ASR-gate seed swap.
3. Per-line LUFS normalization plus HPF 80 Hz.
4. Stretch factors above ~1.2x (Rubber Band alters timbre).
5. Mode-dependent room (hall vs room) and `MODE_BAND_HI`.
6. Script mode's independent per-line renders; `_pick_model` changing the writer.

## Where "cuts" come from
`_trim` internal `silenceremove` (no crossfade); `_pace_sentences` seams at aligned word bounds; PSOLA splices with 3 ms fades; zero-filled chunk joins; `max_tokens` cap of 900 (l.803) truncating long slow chunks; 70 ms fade-out after reverb.
